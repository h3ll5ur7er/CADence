Every version tag publishes installers for the major systems, each with the desktop app and the command line and MCP server for agents ([[CAD-131]]).

- [x] The release workflow builds on Windows x64, macOS (Apple silicon) and Linux x64, into one release with the update files of all three
- [x] Each installer puts the command line next to the app as `cadence-cli` (a Tauri sidecar, `bundle.externalBin`)
- [x] Each release has the command line on its own for each system (`cadence-cli-windows-x64.exe`, `cadence-cli-macos-arm64`, `cadence-cli-linux-x64`)
- [x] The About dialog of the desktop app shows the `claude mcp add` command for the command line installed with it, and links to the releases in the web app
- [x] Pull requests that change how releases are built, and runs by hand, build everything without publishing (workflow artifacts)
- [x] Test: the About dialog's command ([[src/app/about/about-dialog.spec.ts]]); the Windows installers built locally with the command line inside
- [x] Docs: [[Development]] (releases), [[User-guide/Automation]], [[Architecture/Decisions#ADR-51]]

One executable for both is not done: the app is a Rust program, the command line a Node one ([[Architecture/Decisions#ADR-51]]). Not done either: code signing and notarization (Windows SmartScreen and macOS Gatekeeper warn), installers for Intel Macs and Linux on ARM.
