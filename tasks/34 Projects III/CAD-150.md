title: The desktop app follows what agents change
type: feature
status: done
priority: high

The desktop app watches its project folders, so a document an agent changes through the MCP server (another process) updates in the open editor, as other tabs of the app already do.

- [x] Watch the project folders (Tauri file watcher); changes not made by this app become events
- [x] Open components, assemblies and drawings reload; an editor with unsaved input asks first
- [x] The project list and documents panel follow new, renamed and deleted documents
- [x] Test: a document changed on disk updates the open editor

Done: the fs plugin's `watch` (Cargo feature, `fs:allow-watch`) on `projects/`; the Tauri file system remembers what it wrote, so only other processes' changes are reported ([[src/app/platform/tauri-folder-watch.ts]]); the composition root publishes `documentChanged`, `documentDeleted`, `projectChanged`, `projectDeleted` ([[Architecture/Decisions#ADR-53]]). Editors' stores open their document again when it changed elsewhere, and ask first during an input ([[src/app/editor/changed-elsewhere.ts]]); lists follow `ProjectManager.watch`, new documents are announced (`documentCreated`). Tests: [[src/core/composition/folders.spec.ts]], the browser journey across two windows (evidence `phase-34-follows`) and the desktop journey writing a document on disk (CI, evidence `phase-34-desktop-follows`).
