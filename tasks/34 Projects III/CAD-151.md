A library is a project whose components (standard parts, a company's brackets) other projects use without copying: assemblies insert them, and an update of the library reaches every project that uses it, with the version they use recorded.

- [x] A project can be marked as a library; others refer to it
- [x] Assemblies insert library components; references keep the library version, updated when asked (or always)
- [x] Archives and git sync carry the reference (and the library, if asked)
- [x] MCP: list libraries and insert from them
- [x] ADR: how references between projects are stored and resolved
- [x] Test: a library part changes, the assembly that uses it follows

Done ([[Architecture/Decisions#ADR-53a]]): a library is a project with an id of its own (`Project.library`); a project that uses a part keeps a read-only copy of the library version it took, linked by `LibraryLink` (library id, document, version, `follow`), with what it uses and the library's parameters. Updates when asked (the documents panel's Update, `library update`) or on their own (`follow: always`). Archives carry the parts, and the libraries if asked (`libraries/<id>.cadence`); `sync_project` with `libraries` syncs them. MCP: `list_libraries`, `library`, `insert_library_part`. Tests: [[src/core/managers/project/project-libraries.spec.ts]], the follow test in [[src/automation/libraries.spec.ts]], the journey in [[e2e/projects-3.spec.ts]] (evidence `phase-34-library`).
