Run scripts against the open project in the app, and keep them with the project as generators that can be run again with other values.

- [x] A console with an editor (types from the scripting API) in the app
- [x] Scripts kept in the project, with parameters asked before a run
- [x] Runs in a worker; stoppable
- [x] Test: a generator script kept, run twice with two sizes

Notes: the editor's **Scripts and plugins** dialog ([[src/app/editor/scripts-dialog.ts]]). The editor is a plain text area with completions of the API's members (after `cadence.`, `cadence.projects.` or a document) and the API's types to read, from the same list the sandbox is built from; no Monaco, which would add megabytes for one dialog. Scripts are `Project.scripts` (name, source, parameters with default and kind), saved with `setProjectScripts`, so they travel with versions, git and archives. A run goes to a Web Worker (`script.worker.ts`) running the sandbox; its API calls are answered on the main thread by the scripting API over the app's own core; Stop ends the worker. After a run the project's documents are read again, so the open component shows what the script made. Journey: [[e2e/automation-3.spec.ts]].
