Features, generators and exporters others write, loaded by the app and the MCP server: a plugin format, how it is installed, and what it may do.

- [x] ADR: the plugin format, its API (scripting API and engine hooks), sandboxing and versions
- [x] Load plugins in the app and the MCP server
- [x] A sample plugin: a generator and an exporter
- [x] Test: a plugin adds a feature that regenerates

Notes: [[Architecture/Decisions#ADR-60a]]. A plugin is one JavaScript file whose body returns `{ id, name, version, cadence: 1, features, generators, exporters }`; it is installed into a project (`Project.plugins`, with its source), so it travels with the project and its features regenerate in the app and the MCP server alike. A plugin feature (`type: 'plugin'`, document schema 4) is built by the Plugin Engine in the sandbox (outlines with heights, cached by values) and extruded by the Design Manager; another major version of the plugin, or none, fails the feature with the reason. The sample [[public/plugins/trays.cadence-plugin.js]] has a feature (a tray), a generator (a set of trays) and an exporter (OpenSCAD polyhedra). Installed with the Scripts dialog, `cadence install-plugin` or the MCP tool `install_plugin`. Left for later: plugin features in other planes than the origin planes, and component results for assemblies are not marked stale when only a plugin changes (they are when the component changes).
