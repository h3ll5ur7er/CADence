When two people change one document (git sync or versions), the changes are merged by their timeline items and sketch elements, not by choosing one side; only real conflicts are asked.

- [x] Merge timelines by item ids, sketches by element ids, parameters by name
- [x] Conflicts on the same item shown side by side, chosen per item
- [x] Git sync uses it instead of picking a side
- [x] Test: two features added in two places merge into one component

Built ([[Architecture/Decisions#ADR-61]]): `mergeDocuments` in the Revision Engine; git sync merges documents (and `project.json`) changed on both sides with it and reports only the items both changed differently (`SyncConflict.items`), resolved per item (`<path>#<item path>`) in the sync dialog, side by side. Live editing ([[CAD-178]]) uses it to catch up after being away. A feature is one item (its fields depend on each other). Tests: [[src/core/engines/revision/revision.spec.ts]], [[src/core/managers/project/project-sync.spec.ts]] (two features added on two devices), and the journey (a hole and a thicker plate from two browsers).
