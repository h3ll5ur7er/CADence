People sign in, own projects and share them with others to view or edit. This needs a server, which CADence does not have yet: start with an ADR on where accounts and shared projects live (a small self-hostable server, or git hosts as accounts), and decide with the owner before building.

- [x] ADR: server or git hosts, accounts, sign-in (OAuth), storage, cost
- [x] Decision with the owner
- [x] Sign-in in the app, projects owned and shared (view, edit)
- [x] Shared links to view a project in the browser
- [x] Test: a project shared to view, opened by another user

Decided with the owner (2026-10-21): a small self-hostable CADence server ([[Architecture/Decisions#ADR-61a]], [[Architecture/Server]]). Built: `server/` (accounts in one JSON file, OAuth with GitHub and Google, sign-in by name on private servers, projects as git repositories with owners, editors and viewers, view links; a Docker image), Server Access and sharing in the Project Manager, the Share dialog in the editor, **Shared projects…** on the home page and the `/shared` route for view links. Tests: [[server/server.spec.ts]] (sharing over git with roles, links, GitHub sign-in against a stand-in) and the journey (a member opens it, a link shows it to someone without an account).
Not done: an MCP tool for sharing (agents sync with `sync_project` and the token as password); hosting the server for the public app is the owner's to set up.
