Reported by an agent modelling a keyboard enclosure through the MCP server (`cadence.exe mcp`, 2026-10-19/20, projects *KB enclosure* and *KB enclosure simple*), report 1.

A revolve cut on a helical gear with a modelled M8 thread was refused with `Standard_OutOfMemory: Standard_MMgrRaw::Allocate(): malloc failed`. After that every kernel call failed (`null function or function signature mismatch`, `[object WebAssembly.Exception]`, `Expected null or instance of TopoDS_Shape, got an instance of TDF_Label`) in every document, until the process was restarted.

- [x] A kernel that ran out of memory (or trapped) is replaced by a new one; open documents are read again
- [x] The refused feature says the kernel ran out of memory, and the next request works
- [x] Test: a kernel failure in the middle of a session leaves the next requests working

Done in phase 33 ([[Architecture/Decisions#ADR-52]]): `kernelFailure` recognises out of memory and traps, `guarded` engines report them, and the next call loads a new kernel; scripts read open documents again when `Core.kernelGeneration` changed, and the MCP answer says so. The revolve cut of the report is now refused with *the kernel ran out of memory* and the next request works.
