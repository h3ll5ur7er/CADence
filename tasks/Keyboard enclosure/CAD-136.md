Reported by an agent modelling a keyboard enclosure through the MCP server (`cadence.exe mcp`, 2026-10-19/20, projects *KB enclosure* and *KB enclosure simple*), report 4.

A sketch made with `plane: { face }` has its origin at the face's centroid (on a rear wall u = −X, on a bottom face v = −Y), which neither the answer nor `get_component` tells. When the face changes later (a tab added to a flange), the centroid moves, and every point of the sketch with it: countersinks ended up 2.8 mm off.

- [x] `create-sketch` answers and `get_component` list each sketch's origin, u and v
- [x] A sketch on a face keeps its origin and axes when the face grows or shrinks (only following the face's plane)
- [x] Test: a tab added to the face leaves the sketch's points where they were

Done in phase 33: a sketch on a face keeps `anchor` (origin and u) from when it was made; answers give each sketch's `frame`.
