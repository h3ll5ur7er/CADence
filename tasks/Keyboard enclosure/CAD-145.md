Reported by an agent modelling a keyboard enclosure through the MCP server (`cadence.exe mcp`, 2026-10-19/20, projects *KB enclosure* and *KB enclosure simple*), report 13.

The shaft of the assembly *Keyboard*, placed by a revolute joint with offset `{ translate [1, 160.5, 4], angle -78.75, lean 90, tilt 90 }`, has the transform `[0,0.195,-0.981,0, 0,0.981,0.195,0, 1,0,0,0, 1,160.5,4,1]` (local Z → world +X), and `render_picture` shows it so. The app's viewport shows it along about world −X, sticking out of the case: as the transposed rotation would. Instances with only a translation look the same in both. Collision checks then pass for a placement the user does not see.

- [x] Find where the viewport (or the app's assembly state) differs from the core's transforms
- [x] One convention everywhere: viewport, solver, pictures, collision checks (they had one; the old app dropped `lean`)
- [x] Test: a document of a newer schema is listed and refused (the transforms already agreed: no test of them needed)

Done in phase 33: the core, the pictures and the solver agreed; the desktop app installed was built before `lean` existed and dropped it when it saved. Documents are now schema 3, which older apps refuse to open (listed, with a message to update CADence). Update the desktop app.
