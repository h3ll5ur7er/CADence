Reported by an agent modelling a keyboard enclosure through the MCP server (`cadence.exe mcp`, 2026-10-19/20, projects *KB enclosure* and *KB enclosure simple*), report 15.

`export_project` with history, then `import_project`, gives documents with new ids and one version (*Imported from …*), although the archive holds the whole git history; `duplicate` of a project too. Restoring an old version into the copy fails. And `versions` restore with the copy's project and the original's document id restored the original's document without a warning.

- [x] An archive imported where its project is not yet keeps its ids and its history
- [x] Where it is (a copy), the tool says the history stays with the original
- [x] `versions` restores only documents of the project it is given
- [x] Tests: import keeps the history; restore refuses a document of another project

Done in phase 33: a copy of a project (duplicate, or an import of a project that is here) brings the versions of its documents and `copiedFrom` with their earlier ids, so the copy keeps the history and restores with its own ids; `versions` refuses documents of another project.
