---
id: CAD-101
title: Fillet and chamfer faces are named after the first edge when edges carry no hint
type: bug
status: done
priority: medium
labels: [modeling, naming, mcp, found-by-CAD-96]
---

`treatEdges` names each new round or bevel face after the nearest picked edge, but `nearestRef` ([[src/core/engines/modeling/occt-modeling-engine.ts#L501-L505]]) measures only the refs' `hint`. Refs without a hint (every ref an agent or a script writes: `get_component` lists edge names without positions) all count as infinitely far, so every new face gets the first edge's name.

Found in [[CAD-96]] (Wrist pin): a chamfer on `e:f:pin:end|f:pin:side:od` and `e:f:pin:side:od|f:pin:start` names all four bevel faces `f:ch:bevel:e:f:pin:end|f:pin:side:od~1…4`, the ones at the start end included. A later feature that picks "the bevel at the start" gets a name that depends on the order of the edges and breaks when the first edge is removed.

The same happens to fillets: a fillet on four eye-to-shank edges of the Link rod names all four round faces `f:fil:round:e:f:big:side:bigo|f:shank:side:shank:l1~1…4`.

- [x] Measure the distance to the picked edge itself (the element the ref resolves to) when a ref has no hint
- [x] Test: a chamfer on two edges without hints names each bevel after its own edge
- [x] Consider listing edge midpoints (and face centres, as now) in `get_component`, so agents can pass hints

**Done (phase 26).** New round and bevel faces are named after the picked edge nearest their centre, by geometry (`BRepExtrema_DistShapeShape`), hints or not. `get_component` lists face centres and edge middles, which agents can pass as hints.
