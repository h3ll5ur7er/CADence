A modelled thread on a shank whose far end meets a shoulder (a hex, a flange) is accepted as `ok`, shows its marker, and leaves the body unchanged: no flank faces, the same volume. Started from the shoulder end (`flip: true`) the same thread is cut. Found in [[CAD-96]] (Spark plug: an M10 thread under the hex).

## Reproduce

Revolve `[0,-10] [5,-10] [5,6.5] [5.2,6.5] [5.2,10] [0,10]` (XZ) about Z; join a hex (across flats 14 mm) extruded 6 mm from XY. The shank face is now `f:body:side:sp:l2~1` (z −10…0). Add `{ type: 'thread', face: l2~1, size: 'M10', length: '', modelled: true, flip: false }`:

| flip | marker | volume (mm³) | flank faces |
| --- | --- | --- | --- |
| no thread | | 2140.40 | |
| false | origin z −10, up, 10 mm | 2140.40 | 0 |
| true | origin z 0, down, 10 mm | 2044.94 | 5 |

Without the hex, the same thread (flip false) is cut. The groove's end lies in the plane of the shoulder; the boolean probably fails and returns the body unchanged.

Two more things seen on the way:

- The base name `f:body:side:sp:l2`, which no longer exists once the face is split in `~1` and `~2`, is accepted and silently resolved to one of the pieces. An ambiguous name should be refused, or resolved by its hint.
- Nothing checks that a modelled thread removed material.

- [x] Stop the groove short of (or past) a face it would end in, or end it with a run-out, so it cuts in both directions
- [x] Refuse a modelled thread whose cut changes nothing ("The thread could not be cut")
- [x] Refuse references that match several faces (base name of a split face) unless a hint settles it

**Done (phase 26).** Base names of pieces that lie apart need a hint; pieces that touch (two half walls of a hole) stay one face, so `f:x:side:hole` still works.
