Fixing the design mistakes of the radial engine in [[CAD-96]] (round 3), I changed eight components through `edit_component`: rear case (recess for the crankcase boss, larger intake ports), propeller blade (a cylindrical shank), hub (larger sockets), piston (deeper crown), nose case (longer tappet guides), cylinder head (tilted plug bosses, pushrod pocket), tappet (roller, shorter stem) and pushrod (shorter). Each `edit_component` answered with the new geometry. The assembly *Radial engine*, which the same server had open since the session began, kept using the old parts:

- `check_assembly` still reported the overlaps the edits removed, to the last digit (rear case and crankcase 101,712.2 mm³, intake pipes 409.98 mm³ each, hub and blades 9,133.68 mm³ each, master rod and piston 74.01 mm³, nose case and tappets 40.087 mm³ each). It also showed the tilted plugs (an assembly edit) overlapping the old head (75 mm³ each), and the pushrods overlapping the old 60 mm tappet stems (265.5 mm³ each).
- The same check in a new process (`cadence run` with `session.interference()`, same project folder, minutes later) found only three overlaps: crank gear and lay gear (41 mm³), sun and planets (308 mm³, gears not phased) and one pushrod in its head (5.5 mm³).
- Joint frames came from the old parts too. The server placed the tappets for a slider constant of 64.50 mm, while a new process measured 67.09 to 67.89 mm for the edited tappet. Cam link offsets an agent derives from the server's answers are then wrong for everyone else.

So `edit_assembly` answers, `check_assembly`, `render_picture` and `animate_study` describe a state that no longer exists, without saying so. An agent iterating on parts and checking the assembly (the normal loop) is misled. The scripting API keeps assemblies open "until closed" ([[src/automation/api.ts#L779-L789]]), and nothing seems to tell the open assembly session that its components changed in the same process.

- [x] An open assembly picks up new results of its components (from `edit_component`, `undo_component`, the app or another process), as the app's assembly editor does
- [x] Until it has them, its answers say which components are still loading or out of date
- [x] Test: edit a component through the MCP server, then `check_assembly` of an assembly that uses it reflects the change

Fixed in phase 28 ([[Architecture/Decisions#ADR-47]]): an open assembly reads a component again on `resultPublished` (this process: the editor, `edit_component`, `undo_component`), and before each script answer waits for this process's events (`Core.settled()`) and catches up with other processes (`AssemblySession.catchUp()`, by the documents' stamps). Components and assemblies a script has open are opened again when another process changed their document. Checks, pictures, animations, properties and exports refuse with `not-ready`, naming the components still being rebuilt after two minutes; `edit_assembly` lists them under `notReady`. Tests: [[src/automation/automation.spec.ts]] (edit through the server, then through a second core on the same folders), [[src/core/managers/assembly/assembly-manager.spec.ts]].
