Small stumbling blocks met while fixing the radial engine in [[CAD-96]] (round 3), each costing an agent a round of guessing:

- **`edit-feature` cannot change a feature's type, and says it does not exist.** Turning the head's extruded plug boss into a revolve (same id) was refused with "Feature plug does not exist." ([[src/core/managers/design/commands.ts#L494-L498]]), although `plug` was in the timeline. Either allow a new type (references by id stay) or say "plug is an extrude; edit-feature keeps the type".
- **`move-point` on a point held by `fix` does nothing and answers like a success.** Moving the tappet's profile points answered with no change and the profile stayed as it was; the fix relations win over the drag ([[src/core/managers/design/commands.ts#L361-L368]]). An agent needs to hear that the point is fixed (or the fix should move with it).
- **A revolve whose outline touches its axis to within about 0.001 mm fails with "[object WebAssembly.Exception]".** An outline from rounded coordinates with one edge on a separate construction line as axis failed, on the origin plane and on an offset plane; with the outline's own edge as the axis the same revolve built. The kernel's exception should become a message ("the outline crosses the axis"), or a near-coincident edge should count as on the axis.
- **A joint offset can tilt only within one plane of the picked frame.** The offset moves, tilts about the frame's x axis, then turns about the new normal ([[src/core/contracts/assembly.ts]] `offsetFrame`), so from a given frame the joint axis can only lean towards the frame's y axis. For the pushrods it happened to work, because each tappet's x axis was its tangential direction. From a frame with its x axis elsewhere (a component origin, a face with another x) the needed direction cannot be reached. A turn before the tilt (or a direction given as a vector) would allow any direction ([[CAD-113]] follow-up).

- [x] `edit-feature` with a different type: allowed, or refused with a message that says why
- [x] `move-point` on a fixed point is refused with a message, or moves the fix
- [x] Revolve: a clear message when the outline crosses or nearly touches its axis
- [x] Joint offsets: a turn about the normal before the tilt (or an axis direction), so any direction can be reached

Fixed in phase 28 ([[Architecture/Decisions#ADR-47]]):

- `edit-feature` may change the kind (references by id stay; an empty name gets the new kind's default name); on a sketch id it says it is a sketch.
- `move-point` on a fixed point is refused: "Point c is fixed (pin); remove the fix to move it.", with the fix as related id, so the app offers to remove it and move the point.
- The kernel only fails when the outline *crosses* the axis (by 0.0005 mm already); outlines near it but on one side build. A revolve now says "The outline crosses the axis (by 0.0005 mm) …" before it reaches the kernel, and other kernel exceptions are decoded (`StdFail_NotDone: BRep_API: command not done`) instead of "[object WebAssembly.Exception]".
- `offset.lean` turns the frame about its normal before the tilt (the joint panel's *Lean* field), so a joint can point any way from any frame.
