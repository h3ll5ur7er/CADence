Testing a backup of the radial engine ([[CAD-96]], round 3), I imported the `.cadence` archive into an empty projects folder with a `cadence run` script, opened the assembly, computed a motion study and closed it. The script ended while the slowest part (the cylinder head) was still being written: its result `.bin` was complete (348 KB), its `.json` was empty (0 bytes). Opening the assembly again then failed outright:

```
SyntaxError: Unexpected end of JSON input
    at FileSystemAssetAccess.latestResult
    at Session.load
    at DefaultAssemblyManager.open
```

`latestResult` parses the metadata without a guard ([[src/core/access/asset/file-system.ts#L40-L45]]), so one broken cache file stops the whole assembly from opening. The cache can always be rebuilt from the document. The same can happen in the app or the MCP server when the process ends or crashes mid-write.

- [x] A result that cannot be read counts as missing: discard it and regenerate the component
- [x] Write results atomically (to a temporary name, then rename), metadata after the bytes
- [x] `cadence run` waits for pending writes before the process ends
- [x] Test: an empty or truncated result `.json` still opens the component and its assemblies

Fixed in phase 28 ([[Architecture/Decisions#ADR-47]]): result (and asset) metadata that cannot be read counts as missing, and the component is built again. The Node and Tauri file systems write every file to a temporary name and rename it into place (Tauri needs `fs:allow-rename`; Windows' brief refusals while a scanner has the file open are tried again). `cadence run` waits for `cadence.settled()`, so requested rebuilds finish before the process ends. Test: [[src/core/access/asset/asset-access.spec.ts]].
