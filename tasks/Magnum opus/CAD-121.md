title: Publishing a large assembly fails with "Body crank has to be rebuilt first" after a few moves

A `cadence run` script that set the radial engine's crank ([[CAD-96]], 79 instances, 42 pattern copies) to four angles in turn, with an interference check after each, ended with:

```
Error: Body crank has to be rebuilt first.
    at OcctModelingEngine.load
    at OcctModelingEngine.snapshot
```

It happens again on a copy of the project (same four angles); with one angle it does not. `crank` is the first instance, and the message comes from `load` ([[src/core/engines/modeling/occt-modeling-engine.ts#L417-L423]]) when the assembly publishes its result after a save ([[src/core/managers/assembly/default-assembly-manager.ts#L465-L477]]).

Likely cause: the shape store is least-recently-used with 400 entries ([[src/core/access/shape/index.ts#L53-L77]]), and `has()` does not count as a use. `place()` ([[src/core/engines/modeling/occt-modeling-engine.ts#L119-L129]]) keeps a placed copy that already exists (`has(key)`) at its old place in the order. The puts for the other parts in the same call can then evict it before `snapshot()` loads it. After a few moves the store holds the old placed copies of earlier poses (121+ parts each), so the crank's copy from the first pose is among the oldest. Also, `place()` silently leaves out a body whose component shape was evicted (`if (!named) return []`), so a picture, drawing or published result could miss parts without saying so.

A longer script on another copy (a phase scan: 15 link changes, 135 moves of the crank and 75 interference checks of the whole engine in one process) ended with its last two checks failing inside the kernel: `table index is out of bounds`, then `null function or function signature mismatch`. These are WebAssembly faults typical of calling into freed memory, which fits an evicted (and deleted) shape still in use. The 73 checks before answered normally.

- [x] `place()` refreshes a placed copy it reuses (or `has` counts as a use), so one call never evicts its own parts
- [x] A body `place()` cannot find makes the call fail with a message (or is rebuilt), instead of dropping out
- [x] The store's capacity takes an assembly's part count into account (or placed copies of an earlier pose are dropped first)
- [x] A shape a running computation holds is not deleted by eviction (no WebAssembly faults in long scripts)
- [x] Test: an assembly with more parts than a quarter of the store's capacity, moved a few times, publishes its result

Fixed in phase 29 ([[Architecture/Decisions#ADR-48]]): open assemblies and drawings hold their components' shapes in the shape store (`ShapeAccess.keep`, counted per holder, released on close), so other work never evicts them, and held entries do not count against the capacity. An assembly's result is now one call, `snapshotPlaced`: the placed copies are made, snapshot and freed, never stored, so publishing cannot evict its own parts. A body that is gone fails by name ("Body … has to be rebuilt first.") instead of dropping out. Tests: [[src/core/access/shape/shape-access.spec.ts]], the small store case in [[src/core/engines/modeling/modeling-engine.spec.ts]].
