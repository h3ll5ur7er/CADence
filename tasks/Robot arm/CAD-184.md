title: Joints take offsets and values that are not numbers, and the assembly moves to nowhere

status: done

Trying whether a joint offset follows a parameter ([[CAD-182]]), `edit-joint` on the robot arm's elbow took `"offset": {"translate": ["upper", 0, 0], …}`. It was applied without a word, and the answer moved twelve instances to `[null, null, null]`: everything after the elbow had NaN transforms, and the document was saved that way. Setting the number back repaired it.

`set-joint-values` refuses text ("Each degree of freedom needs a number"), but `checkJoint` ([[src/core/managers/assembly/commands.ts#L69-L77]]) looks only at the instances, the number of values and the limits' order. It does not check that the offset's translate, lean, tilt and angle, the joint's values and the limits' minimum and maximum are finite numbers.

- [x] `add-joint`, `edit-joint` and `insert-instance` with a joint refuse offsets, values and limits that are not finite numbers, naming the field
- [x] A document whose transforms are not finite is never saved: the command fails instead
- [x] Tests: a text in each offset field, a NaN value, a limit of `null` min

Fixed in phase 44 ([[Architecture/Decisions#ADR-63]]): `checkJoint` ([[src/core/managers/assembly/commands.ts]]) refuses offsets, values, limits and cones that are not finite numbers, naming the field ("The first offset's translate needs three numbers (mm); use expressions for parameters."). Transforms of inserted and moved instances must be 16 numbers, and a change that would give an instance a position that is not a number is refused before it is saved. Tests: *refuses joints whose offsets, values or limits are not numbers* in [[src/core/managers/assembly/assembly-manager.spec.ts]].
