The undo history lives in the server's open session of a document. A server started after the change (a new MCP process, as an agent's tools often are) has none. `undo_assembly` then answers with the assembly's counts, like an undo that changed nothing visible, and the agent believes it went back ([[CAD-183]]: four undos after four leg changes left the platform as it was). `undo_component` behaves the same way. The handler undoes and reports the difference without asking whether there was anything to undo ([[src/automation/mcp.ts#L435-L443]]).

- [x] undo and redo with nothing to undo or redo say so (an error the agent sees), for components, assemblies and drawings
- [x] The tools' descriptions say the history is the server session's, and that versions (`versions`) go back further

Fixed in phase 44: undo_component, undo_assembly and undo_drawing answer with an error when there is nothing to undo or redo ("Nothing to undo: this server made no change to the document since it opened it. Changes from before (or from other processes) are in its version history: versions."), and their descriptions say the history is the server session's.
